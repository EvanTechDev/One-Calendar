Publish a specification as a parent issue, then publish the approved implementation
slices as child issues in dependency order. Record dependencies using Linear's
native blocking relationships, as well as the issue's Blocked by section.

Use the label mapping in `triage-labels.md`. A fully specified implementation
ticket receives `ready-for-agent`; its blockers determine when work can begin.
Get approval for the proposed breakdown before publishing its implementation
tickets. Creating child issues does not authorize closing or otherwise editing
an existing parent issue.

Read existing issues before creating replacements or changing their content.
Use the integration's discovered tool schemas and preserve real newlines in
Markdown descriptions. Do not delegate or assign issues unless requested.
